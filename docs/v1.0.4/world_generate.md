# 世界壳生成

本文描述 v1.0.4 的“世界生成”定义。

这份文档只讨论世界壳生成，不讨论课程剧情生成。课程剧情只能在课程创建流程里生成。

## 1. 产品定位

本次世界壳创建流程，全程恪守4条核心规则，精准区分「世界基底」和「课程剧情交互」，避免功能越界：

1. 只定世界，不定教学：仅回答「世界是什么场景、有什么基础规则」，不涉及课程大纲、课时剧情、角色互动机制、复习/教学事件等内容，完全剥离后续教学模块。
2. 轻量化低门槛：流程步骤极简，无复杂专业参数，普通用户3-5分钟即可完成创建，拒绝冗余配置。
3. 遐想感拉满：以「场景氛围、世界观基调」为核心，引导用户填充感性、画面感内容，而非冰冷设定，激发用户对专属学习世界的想象。
4. 高兼容适配：创建完成的世界壳为「通用基底」，可后续适配任意学科课程、任意自定义角色，不绑定具体学习内容。

世界生成只负责创建一个长期可复用的舞台壳：

- 世界名称
- 世界说明
- 默认背景图

其中：

- `World.description` 承载世界舞台说明。
- `World.background_picture` 承载默认背景图。

也就是说，世界创建阶段只回答两个问题：

1. 这个世界看起来是什么地方。
2. 这个世界的基础设定是什么。

它不回答这些问题：

1. 这门课准备怎么展开。
2. 角色之间如何互动。
3. 每一课会触发什么剧情。
4. 教学事件和复习事件是什么。

## 2. 最小数据结构

`World` 本体承载：

- `World.name`
- `World.description`
- `World.background_picture`

字段说明：

- `description`
  世界舞台说明。
- `background_picture`
  默认背景图资源。这里不用 `background`，避免和抽象背景设定混淆。

## 3. 用户流程

世界壳创建流程应当尽量简单：

1. 只问一个问题，让用户用一句话描述心中世界的"感觉"：
"如果这个世界是一部电影/一部小说，它的海报/封面是什么样的？请用一句话描述你脑海中浮现的画面。"

示例参考：
- "一座建在巨鲸背上的移动学院，四季如春，鲸鱼缓慢地游过星海。"
- "地下深处的灯火之城，人们用发光的文字交换故事，地面早已无人踏足。"
- "雨永远不停的小镇，每家店铺的屋檐下都挂着一串风铃，风铃里藏着别人的记忆。"）

（等待用户点击确认后，进入第二步）

2. 骨架填充（结构化追问）

基于用户的一句话，用 3-4 个固定维度的问题帮用户把世界"立起来"。每个维度只问一个核心问题，避免疲劳：

- 时空锚点：这个世界在什么时代（古代/现代/未来/架空）什么尺度？（一座城/一片大陆/一艘船）
- 核心氛围：走进这个世界，最强烈的感受是什么？（宁静/冒险/神秘/温暖/荒凉）
- 运转规则：这个世界有一条与众不同的"底层规则"是什么？（比如"知识是货币""记忆可以交易""每个人出生时都会获得一本空白之书"）
- 背景图样：用户选择或上传 `background_picture`。

（等待用户点击确认后，进入第三步。注意，第二步点击确认后，就将一二问答案递送给ai，由ai返回完善后的世界观）

（以下为系统提示词，不展示给用户）

你是一位擅长世界观构建的叙事设计师。请根据用户提供的骨架信息，创作一段完整的世界观描述。

创作原则：
1. 忠于用户的核心设定，不擅自添加与用户设定冲突的元素
2. 在氛围渲染、感官细节、意象延展上做文学性扩展
3. 语言风格要有画面感和情绪张力，像游戏开场动画的旁白
4. 长度控制在 150-300 字
5. 结尾留一个开放式的"钩子"，暗示这个世界里即将发生的故事

输出格式：

> ### [建议的世界壳名称]
>
> [世界观描述正文]


3. 确认与命名

以下是你创造的世界，请确认或修改：

> **[建议的世界壳名称]**
>
> 这是一个[时空锚点]的世界。[一句话画面描述]。
> 这里最独特的规则是：[运转规则]。
> 整个世界的氛围是[核心氛围]的，它的底色由[视觉基调]构成。
>
> [世界观描述正文]

请确认以上描述是否相符，如有需要可任意修改。




创建完成后，用户进入这个世界壳。

进入世界壳之后，才开始课程创建流程。

## 4. AI 生成接口的目标

`POST /world/generate` 的目标也应该跟着缩小。


目标返回形态：

```json
{
  "name_suggestion": "建议的世界壳名称",
  "description": "世界观描述正文",
  "background_picture": "/themes/academy.jpg"
}
```

这里 `background_picture` 可以是：

- 预设资源路径
- 用户后续手选的默认占位

## 5. 前端表单原则

应该保留：

- 世界名称
- 世界说明 `description`
- 背景图 `background_picture`

前端生成完成后，提交 payload 的目标语义应该是：

```json
{
  "name_suggestion": "建议的世界壳名称",
  "description": "世界观描述正文",
  "background_picture": "/themes/academy.jpg"
}
```

## 6. 与课程创建的边界

世界壳创建完成后，进入世界内部，课程创建流程必须按下面顺序进行：

1. 根据教材知识结构生成课程教学结构。
2. 引入角色。
3. 根据世界壳和角色生成课程叙事结构。

换句话说：

- 世界壳不直接生成课程剧情。
- 没有教材，不生成课程叙事。
- 没有角色，不生成课程叙事。
- 课程叙事只从“课程教学结构 + 世界壳 + 角色”派生。
